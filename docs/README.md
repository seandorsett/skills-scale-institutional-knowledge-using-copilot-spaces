# OctoAcme Project Management Docs

Use this guide to understand OctoAcme's project management approach and find detailed guidance for each stage of delivery.

## Project management processes summary

OctoAcme follows a customer-first, iterative lifecycle: initiation, planning, execution, release, and closeout with a retrospective. Initiation captures the business problem, measurable goals, stakeholders, initial risks, and resource needs in a Project One-pager. Planning turns an approved initiative into a prioritized backlog with acceptance criteria, estimates, a Definition of Done, dependencies, and agreed milestones.

Project Managers coordinate delivery, schedules, risks, and communications. Product Managers define outcomes, prioritize work, and measure value. Developers design, implement, test, and review changes; QA validates quality and acceptance criteria; stakeholders provide input and approvals. Teams use a project board to track small, reviewable increments from Backlog through Ready, In Progress, In Review, QA, and Done.

Standups surface progress and blockers, weekly delivery and PM/Product Manager syncs align work, and sprint or milestone demos make progress visible. Regular stakeholder updates cover achievements, next steps, risks, and decisions needed, with a project README or release document serving as the status source of truth. Teams maintain a risk register and escalate unresolved issues through the PM, Product Lead, and sponsor.

Quality practices include unit and integration tests, CI tests and linting, security scanning, critical-flow smoke tests, manual acceptance testing when needed, and pull request approval under the team's policy. Releases require passing checks, release notes, a rollback or mitigation plan, staging verification, and post-deployment checks. Retrospectives turn lessons into prioritized backlog actions with owners, due dates, and success criteria, reviewed in the weekly PM sync.
